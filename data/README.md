# Data layout

Large arrays and externally licensed files are not tracked by Git.

## Velocity model

Place a three-dimensional `float32` NumPy array at:

```text
data/velocity/vp_model.npy
```

The current configuration uses physical lengths of 20,000 m, 20,000 m, and
4,650 m along the three array axes. Verify the axis order against the receiver
and source coordinates before training.

## Observation archive

Each event is a compressed NumPy archive such as
`data/observations/event_01.npz` with:

| Field | Shape | Unit | Required |
|---|---:|---|---|
| `data` | `[n_receiver, n_time]` | waveform convention | yes |
| `times` | `[n_time]` | s | yes |
| `receiver_coords` | `[n_receiver, 3]` | m | yes |
| `source_truth` | `[4]` | m, m, m, s | for validation |

The `source_truth` order is `(xs, ys, zs, ts)`. The inversion script never uses
it to form predictions; it only computes reported errors.

Do not validate the method using a waveform generated by the same approximate
average-velocity template used by the legacy inversion.
